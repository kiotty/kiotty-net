kiotty_net_base.h 구현 설계 v1

2026-10-29. design_base_v0.md 와 피드백 v0 ~ v5, v5 의 마지막 여섯 답 (cancel 없음, Nagle 설정, onTick 없음, arm → submit, step 의 모양, broadcast 우선), 그리고 v1 초안 검토의 열 답을 모두 합친 문서다. 이 문서는 클래스의 인터페이스와 한 바퀴의 순서 를 정한다. 각 클래스의 안 (OS 호출, 자료구조) 은 구현하면서 따로 논의한다. 두 문서가 다르면 requirement 가, 흐름이 다르면 implementation_guide 가 우선한다.

확정 v0 ~ v5 에서 끝난 것 이번 v5 의 마지막 답으로 정해진 것 검토 v1 초안 검토의 답으로 바뀐 것 추천안 없음. 모든 결정이 끝났다

원칙 셋은 v0 그대로다.

  1. src/kiotty_net_base.cpp 는 번역만 한다. C 의 handle 과 struct 를 구현 객체로 바꿔 메서드 하나를 부르고 결과를 C 타입으로 돌려준다. 검사, 분기, 상태 변경, 복사를 두지 않는다 (15절 표).
  2. 클래스는 목적에 필요한 최소 함수와 최소 변수 만 가진다. 상태를 읽어 판단하는 줄은 이 문서에 적힌 자리 (pending() 셋) 밖에 두지 않는다.
  3. 의존은 아래로만 간다. OS 가 다른 부분은 그 폴더의 backend/ 안에만 있다. OpenSSL 은 tls/ 안에만 있다.

2. 공용 규약

  • core/ 는 namespace kiotty, base/ 는 namespace kiotty { namespace net { } }. 내부 타입에 접두어는 없다.
  • 공개 struct (KiottyNetSpan, KiottyNetEndpoint, KiottyNetTransport, 설정 struct, KiottyNetConnectionHandler, KiottyNetConnectionInfo, KiottyNetConnectionAction, KiottyNetConnectionDecision) 는 내부에서도 그대로 쓴다.
  • 내부 에러는 Result<Code, Value> 와 코드 enum 으로 돌려준다. SocketCode → KiottyNetCode 변환은 Connection 과 StreamClient 에서만 한다. output 인자는 없다.
  • pool handle 은 PoolHandle { int32_t generation; int32_t index; }, 0 은 무효. index 의 비트 배치는 13.3.
  • 모든 메모리는 create 시점의 생성자에서 잡는다. 그 뒤 new / malloc 은 없다. 잡지 못하면 valid() == false 이고 create 의 Result.code 가 이유다. OpenSSL 의 내부 할당은 Context 의 Pool 로 간다 (13절).
  • 클래스는 복사하지 않는다. slot 안에 사는 것 (Connection, Owner) 은 이동도 하지 않는다.
  • 콜백은 IO Thread 에서, dispatch 와 onOpened 안에서만 나간다. 콜백이 안 나가는 자리 (resolve, submit, settle, onNotified) 는 handler 를 받지 않는다.
  • IO Thread 밖에서 EventListener 에 들어가는 호출은 wake() 하나다. 다른 thread 는 적고 (WorkContext, Notification Stage) 깨운다.
  • 들어온 것을 처리하는 함수는 전부 on* 이다. completion 을 받는 것 (onReceived, onSent, onTimeout, onWorkFinished) 과 아닌 것 (onOpened, onHandshake, onNotified, onPeerGone) 모두 IoAction 을 돌려준다.

5. IoAction, IoPayload, IoCompletion 확정

세 타입이 세 동작을 잇는다. dispatch 는 completion 을 받아 action 을 내고, resolve 는 action 을 받아 payload 를 내고, submit 은 action 과 payload 를 listener 에 준다. 서로 다른 타입이라 섞일 수 없다.

IoCompletion ──▶ dispatch ──▶ IoAction ──▶ resolve ──▶ IoPayload ──▶ submit ──▶ OS ──▶ IoCompletion (OS 또는 IoLoop) Stage 갱신 (뜻) Stage 를 (자리) listener 에 (걸었던 action 을 싣고) + handler 보고 계산 action + payload
enum class IoActionKind : uint8_t { NONE, HOLD, READ, READ_UNTIL, WRITE, START_WORK, CLOSE, ACCEPT };
enum class IoPurpose    : uint8_t { USER, HANDSHAKE, CONTROL, NOTIFY };   // 완료를 어느 Stage 로 돌려주나. CONTROL 은 TLS 의 KeyUpdate 답장

struct IoAction                                 // 뜻. handler 가 준 것 + Connection 이 덧붙인 purpose
{
    IoActionKind kind;
    IoPurpose    purpose;
    uint32_t     timeout_ms;
    union
    {
        struct
        {
            size_t exact;
        } read;
        struct
        {
            char    delimiter[4];
            uint8_t length;
            size_t  max;
            size_t  scanned;                    // 진행 위치. Connection 이 따로 들지 않는다
        } read_until;
        struct
        {
            KiottyNetCode reason;
        } close;
    } as;

    static IoAction none();
    static IoAction hold(uint32_t timeout_ms);
    static IoAction read(IoPurpose purpose, uint32_t timeout_ms, size_t exact);           // HANDSHAKE 는 exact 0 (오는 만큼)
    static IoAction write(IoPurpose purpose, uint32_t timeout_ms);                         // 보낼 바이트는 이미 Stage 에 있다
    static IoAction startWork();
    static IoAction close(KiottyNetCode reason);
    static IoAction accept();
    static IoAction from(const KiottyNetConnectionAction& action);                        // purpose USER. WRITE 의 data 는 Connection::adopt 가 Stage 로 옮긴다 (9.4)
};

struct IoPayload                                // 자리. resolve 가 만들고 listener 가 OS 에 넘긴다
{
    void*  buffer;
    size_t length;
};

enum class IoKind : uint8_t { ACCEPT, RECEIVE, SEND, WAKE,       // EventListener::wait 가 돌려준다
                              TIMEOUT, WORK_DONE };              // IoLoop::collect 가 만든다

struct IoCompletion
{
    IoKind     kind;
    int32_t    slot;                            // ACCEPT / WAKE 는 -1
    SocketCode code;                            // SUCCESS, CLOSED (0 바이트), CANCELLED (닫힌 소켓의 늦은 완료), 그 밖의 오류
    size_t     length;
    IoAction   action;                          // RECEIVE / SEND / ACCEPT : 걸었던 action 그대로 (값). TIMEOUT / WORK_DONE / WAKE : NONE

    static IoCompletion timeout(int32_t slot);  // collect 가 만든다
    static IoCompletion workDone(int32_t slot);
};
  • 사용자의 WRITE 데이터는 IoAction 에 없다. KiottyNetConnectionAction 의 span 은 Connection::adopt 가 송신 Stage 에 복사한 뒤 버린다. 그래서 IoAction 은 사용자 메모리를 가리키지 않고, 완료가 싣고 돌아와도 안전하다.
  • completion 이 action 을 값으로 싣는다 (약 40 바이트). Connection 은 "지금 걸린 read 조건" 을 기억하지 않는다. 조건은 action 안에 있고 완료가 가져온다.
  • 공개 KiottyNetConnectionAction 에는 ACCEPT 가 없다. 사용자가 return 할 수 없는 kind 는 from() 이 만들지 않는다.

7. event : EventListener 확정

OS 의 다중화 객체 하나다. 어느 backend 에서도 proactor 처럼 보이게 한다. submit 에 payload 를 넘기면 IOCP 는 kernel 이 거기에 쓰고, epoll 은 readable 통지 뒤 listener 가 recv 해서 거기에 쓴다. 호출자는 완료의 길이만 본다.

8. tls : TlsProfile, TlsEngine 확정

데이터 흐름에서는 TLS 가 socket 뒤에 있고 (socket → 암호문 StageSet → TlsEngine → 평문 StageSet), include 의존에서는 옆에 있다 (TlsEngine 은 socket 헤더를 포함하지 않는다. 바이트만 다룬다). SSL_set_fd 로 socket 을 TLS 에 넘기지 않는 이유는 overlapped / proactor 의 recv 소유권과 충돌하기 때문이다. memory BIO 로 completion 마다 한 걸음 간다.

이름 TlsEngine 의 근거는 Java 의 SSLEngine 이다. socket 없이 바이트 버퍼만 받아 handshake 상태 (NEED_WRAP / NEED_UNWRAP) 를 돌려주는 전송 독립 TLS 상태 기계이고, 그것이 정확히 이 클래스다. TlsStream 은 .NET 의 SslStream 처럼 자기가 IO 를 하는 것으로 읽혀서 피했다.

TlsStep TlsEngine::handshake()
{
    int result = SSL_do_handshake(_ssl);
    moveWbioToCipherSend();
    if (_cipher.send.consumer().readable() > 0)
    {
        return TlsStep::SEND;                   // DONE 직후의 NewSessionTicket 도 여기 걸린다
    }
    if (result == 1)
    {
        return TlsStep::DONE;
    }
    if (SSL_get_error(_ssl, result) == SSL_ERROR_WANT_READ)
    {
        return TlsStep::RECEIVE;
    }
    recordError();
    return TlsStep::FAILED;
}

9.1 IoSource : submit 이 보는 인터페이스 이번

9.4 dispatch : completion → on* → apply

규칙 셋. completion 을 처리하는 함수는 전부 on* 이고 첫 인자가 const IoCompletion& 다. Phase 로 먼저 자르고, completion.action.purpose 로 switch 하고, TLS 분기는 그 안의 한 줄이다. 모든 hook 은 IoAction 을 돌려주고, 콜백이 안 나간 hook 은 NONE 을 돌려준다. handler 의 return 은 지역 변수 returned 로 받고 adopt 에 넘긴다. 중첩 호출은 쓰지 않는다.

IoAction Connection::dispatch(const IoCompletion& completion, const Handler& handler)
{
    IoAction action = IoAction::none();
    switch (completion.kind)
    {
    case IoKind::RECEIVE:
        action = onReceived(completion, handler);
        break;
    case IoKind::SEND:
        action = onSent(completion, handler);
        break;
    case IoKind::TIMEOUT:
        action = onTimeout(completion, handler);
        break;
    case IoKind::WORK_DONE:
        action = onWorkFinished(completion, handler);
        break;
    }
    return apply(action, handler);
}

IoAction Connection::apply(IoAction action, const Handler& handler)         // listener 없음. Connection 과 handler 만
{
    switch (action.kind)
    {
    case IoActionKind::NONE:
        return action;
    case IoActionKind::HOLD:
    case IoActionKind::READ:
    case IoActionKind::READ_UNTIL:
    case IoActionKind::WRITE:
        setDeadline(action.timeout_ms);
        return action;
    case IoActionKind::START_WORK:
        _deadline = 0;
        _work.start(generation());
        handler.onWorkStarted(_context, workHandle());
        return action;
    case IoActionKind::CLOSE:
        _deadline = 0;
        _phase = Phase::CLOSING;
        handler.onDisconnected(_app_context, _context, handle(), action.as.close.reason);   // accept 된 연결은 반드시 한 번
        return action;
    }
}

IoAction Connection::onOpened(const Handler& handler)
{
    IoAction action = IoAction::none();
    if (_tls.active())
    {
        action = onHandshake(handler);                                         // 서버 : RECEIVE → READ(HANDSHAKE). 클라이언트 : ClientHello → SEND → WRITE(HANDSHAKE)
    }
    else
    {
        KiottyNetConnectionAction returned = handler.onReady(_context, handle());
        action = adopt(returned, handler);
    }
    return apply(action, handler);
}

IoAction Connection::onHandshake(const Handler& handler)                      // HANDSHAKING 의 모든 completion 뒤
{
    switch (_tls.handshake())
    {
    case TlsStep::SEND:
        return IoAction::write(IoPurpose::HANDSHAKE, _handshake_timeout_ms);
    case TlsStep::RECEIVE:
        return IoAction::read(IoPurpose::HANDSHAKE, _handshake_timeout_ms, 0);
    case TlsStep::DONE:
    {
        _phase = Phase::READY;
        KiottyNetConnectionAction returned = handler.onReady(_context, handle());
        return adopt(returned, handler);
    }
    case TlsStep::FAILED:
        handler.onError(_app_context, handle(), _tls.lastCode(), _tls.lastMessage());
        return IoAction::close(_tls.lastCode());
    }
}

IoAction Connection::onReceived(const IoCompletion& completion, const Handler& handler)
{
    if (_phase == Phase::CLOSING)
    {
        return IoAction::none();                                               // 늦은 완료 (CANCELLED 포함). settle 이 event 가 비었는지만 본다
    }
    if (completion.code != SocketCode::SUCCESS)
    {
        return onPeerGone(completion.code);                                    // CLOSED (0 바이트) 포함
    }
    receiveStage(completion.action.purpose).provider().commit(completion.length);
    if (completion.action.purpose == IoPurpose::HANDSHAKE)
    {
        return onHandshake(handler);
    }
    if (_tls.active())
    {
        KiottyNetCode decoded = _tls.decode(_plain.receive);                   // cipher → plain. 레코드가 덜 찼으면 0 바이트
        if (decoded != KIOTTY_SUCCESS)
        {
            handler.onError(_app_context, handle(), decoded, _tls.lastMessage());
            return IoAction::close(decoded);
        }
        if (_tls.hasControlOutput())
        {
            _resume_read = completion.action;                                  // 답장을 보내는 동안 READ 를 미룬다. onSent(CONTROL) 이 pump 로 되살린다
            return IoAction::write(IoPurpose::CONTROL, 0);
        }
    }
    return pump(completion.action, handler);                                   // 걸었던 READ 조건을 Stage 에 대 본다
}

IoAction Connection::onSent(const IoCompletion& completion, const Handler& handler)
{
    if (_phase == Phase::CLOSING)
    {
        return IoAction::none();
    }
    if (completion.code != SocketCode::SUCCESS)
    {
        return onPeerGone(completion.code);
    }
    Stage& out = sendStage(completion.action.purpose);
    switch (completion.action.purpose)
    {
    case IoPurpose::NOTIFY:
        consumeNotification(out, completion.length);
        return onNotified();                                                   // 그 사이 쌓인 것이 있으면 바로 다음 WRITE(NOTIFY). 없으면 NONE
    case IoPurpose::HANDSHAKE:
        out.consumer().commit(completion.length);
        return onHandshake(handler);
    case IoPurpose::CONTROL:
        out.consumer().commit(completion.length);
        return pump(_resume_read, handler);                                    // 미뤄 둔 READ. decode 된 평문이 이미 조건을 채웠으면 onRead 가 바로 나간다
    case IoPurpose::USER:
    {
        out.consumer().commit(completion.length);
        if (out.consumer().readable() > 0)
        {
            return IoAction::write(IoPurpose::USER, completion.action.timeout_ms);   // 남은 조각
        }
        out.compact();
        KiottyNetConnectionAction returned = handler.onWritten(_context, handle(), _write_length);
        return adopt(returned, handler);
    }
    }
}

void Connection::consumeNotification(Stage& out, size_t sent)
{
    std::lock_guard<std::mutex> lock(_notification.mutex);
    out.consumer().commit(sent);
    if (_tls.active())
    {
        _plain.notify.consumer().commit(_notify_plain_length);
    }
    if (out.consumer().readable() == 0)
    {
        out.compact();                                                         // 걸린 send 가 없을 때만 compact 한다
    }
}

IoAction Connection::onTimeout(const IoCompletion&, const Handler& handler)          // 11절의 규칙
{
    if (_phase == Phase::HANDSHAKING)
    {
        handler.onError(_app_context, handle(), KIOTTY_TLS_HANDSHAKE_TIMEOUT, "tls: handshake timeout");
        return IoAction::close(KIOTTY_TLS_HANDSHAKE_TIMEOUT);
    }
    KiottyNetConnectionAction returned = handler.onTimeout(_context, handle());
    if (_stream_event.pending())
    {
        return extend(returned, handler);                                      // 걸린 요청이 있다. adopt 를 거치지 않으므로 stageWrite 의 부작용이 없다
    }
    return adopt(returned, handler);                                           // 걸린 것이 없다 (HOLD 뒤). 평소대로
}

IoAction Connection::extend(const KiottyNetConnectionAction& returned, const Handler& handler)
{
    if (returned.type == KIOTTY_ACTION_CLOSE)
    {
        return IoAction::from(returned);                                       // 닫는다. 걸린 요청은 CANCELLED 완료로 돌아온다
    }
    if (returned.type == KIOTTY_ACTION_WRITE || returned.type == KIOTTY_ACTION_START_WORK)
    {
        handler.onError(_app_context, handle(), KIOTTY_BUSY, "action rejected: io outstanding. use notify");
    }
    setDeadline(returned.timeout_ms);                                          // 걸린 요청은 그대로. 기다림만 연장한다. START_WORK 의 0 은 "더 재지 않는다"
    return IoAction::none();
}

IoAction Connection::onWorkFinished(const IoCompletion&, const Handler& handler)
{
    IoAction outcome = _work.onFinished();                                     // DONE → IDLE. WRITE 면 worker 가 _plain.send 를 이미 채웠다
    if (_peer_closed.load())
    {
        return IoAction::close(KIOTTY_PEER_CLOSED);
    }
    if (outcome.kind == IoActionKind::WRITE && _tls.active())
    {
        encodeSendStage();                                                     // 암호화는 IO Thread 만
    }
    if (outcome.kind == IoActionKind::READ || outcome.kind == IoActionKind::READ_UNTIL)
    {
        return pump(outcome, handler);                                         // 남아 있던 바이트로 바로 찰 수 있다
    }
    return outcome;
}

IoAction Connection::onPeerGone(SocketCode code)
{
    if (_work.working())
    {
        _peer_closed.store(true);                                              // Work 중 (notify 완료로만 올 수 있다). 기록만. onWorkFinished 가 닫는다
        return IoAction::none();
    }
    if (code == SocketCode::CLOSED)
    {
        return IoAction::close(KIOTTY_PEER_CLOSED);
    }
    return IoAction::close(KIOTTY_SOCKET_ERROR);
}

IoAction Connection::adopt(const KiottyNetConnectionAction& returned, const Handler& handler)
{
    IoAction action = IoAction::from(returned);
    if (action.kind == IoActionKind::WRITE)
    {
        return stageWrite(returned.as.write.data);
    }
    if (action.kind == IoActionKind::READ || action.kind == IoActionKind::READ_UNTIL)
    {
        return pump(action, handler);
    }
    return action;
}

IoAction Connection::pump(IoAction read, const Handler& handler)              // 재귀 아닌 loop
{
    for (;;)
    {
        Result<KiottyNetCode, KiottyNetSpan> ready = satisfied(read, _plain.receive);   // exact > capacity, max 초과 : REQUEST_TOO_LARGE. 안 찼으면 빈 span (scanned 전진)
        if (!ready)
        {
            return IoAction::close(ready.code());
        }
        if (ready.value().length == 0)
        {
            return read;                                                       // 더 받아야 한다. resolve 가 자리를 잡고 submit 이 건다
        }
        KiottyNetConnectionAction next = handler.onRead(_context, handle(), ready.value());
        _plain.receive.consumer().commit(ready.value().length);                // 콜백이 돌아온 뒤 소비. data 는 콜백 동안만 유효하다
        IoAction action = IoAction::from(next);
        if (action.kind == IoActionKind::WRITE)
        {
            return stageWrite(next.as.write.data);
        }
        if (action.kind != IoActionKind::READ && action.kind != IoActionKind::READ_UNTIL)
        {
            return action;
        }
        read = action;                                                         // READ 가 또 왔고 Stage 에 또 차 있을 수 있다
    }
}

HANDSHAKINGcipher.receive.commit → onHandshakecipher.send.commit → onHandshakeonError(HANDSHAKE_TIMEOUT) → CLOSE오지 않는다

9.5 resolve : action → payload

IoPayload Connection::resolve(const IoAction& action)                        // 콜백 없음, listener 없음. 분기는 kind 둘, Stage 는 purpose 가 고른다
{
    switch (action.kind)
    {
    case IoActionKind::READ:
    case IoActionKind::READ_UNTIL:
    {
        Stage& in = receiveStage(action.purpose);
        size_t room = in.provider().writable();
        return IoPayload{ in.provider().prepare(room), room };
    }
    case IoActionKind::WRITE:
    {
        Stage& out = sendStage(action.purpose);
        size_t ready = out.consumer().readable();
        return IoPayload{ out.consumer().peek(), ready };
    }
    default:
        return IoPayload{ nullptr, 0 };
    }
}

dispatch 의 WRITE 가 이미 Stage 에 복사 (+ encode) 했고, READ 가 이미 pump 로 "찼으면 onRead" 를 끝냈으므로 resolve 는 Stage 만 본다. 이것이 dispatch / resolve / submit 의 역할 분담이 맞았다는 증거다.

9.6 WorkContext

start() IO Thread IDLE ──▶ WORKING apply(START_WORK). 그 뒤 onWorkStarted. 이 연결의 콜백은 WORK_DONE 까지 없다 finish() worker WORKING ─▶ DONE outcome 을 넣고 CAS (release). 그 뒤 listener.wake() onFinished() IO Thread DONE ──▶ IDLE collect 가 DONE 을 보면 WORK_DONE completion. onWorkFinished 가 outcome 을 꺼낸다
class WorkContext
{
public:
    enum class State : uint8_t { IDLE, WORKING, DONE };
    void          start(int32_t generation);                       // IO Thread
    bool          finished() const;                                // collect. load(acquire) == DONE
    IoAction      onFinished();                                    // IO Thread. DONE → IDLE
    bool          working() const;                                 // WORKING 또는 DONE. 콜백을 내면 안 되는 구간
    void          reset();
    KiottyNetCode finish(int32_t generation, IoAction outcome);    // worker. generation 이 다르면 PEER_CLOSED. WORKING 이 아니면 BUSY. _outcome 뒤 CAS (release)
    bool          matches(int32_t generation) const;
private:
    std::atomic<State> _state;
    int32_t            _generation;
    IoAction           _outcome;
};

KiottyNetCode Connection::finishWork(int32_t generation, const KiottyNetConnectionAction& action)   // 아무 thread
{
    if (!_work.matches(generation))
    {
        return KIOTTY_PEER_CLOSED;
    }
    if (action.type == KIOTTY_ACTION_START_WORK)
    {
        return KIOTTY_INVALID_ARGUMENT;
    }
    IoAction outcome = IoAction::from(action);
    if (outcome.kind == IoActionKind::WRITE)                                   // worker 가 _plain.send 에 직접 쓴다. Work 중 IO Thread 는 _plain.send 를 만지지 않는다. 평문 그대로 (encode 는 IO Thread)
    {
        KiottyNetSpan data = action.as.write.data;
        if (_plain.send.provider().writable() < data.length)
        {
            return KIOTTY_BUFFER_FULL;
        }
        copy data into _plain.send;
        _write_length = data.length;
    }
    KiottyNetCode code = _work.finish(generation, outcome);                    // Stage 복사 → CAS (release) → wake. IO Thread 가 DONE 을 본 시점에 Stage 는 차 있다
    if (code == KIOTTY_SUCCESS)
    {
        _notification.listener->wake();
    }
    return code;
}

Owner 의 close 는 WORKING 인 연결도 바로 닫고 generation 을 올린다. 늦게 온 finishWork 는 matches 가 거짓이라 PEER_CLOSED 로 끝난다. worker 가 그때 Session 을 쓰고 있을 수 있는 것은 사용 지침으로 적는다 (v0 15-7).

9.7 NotificationContext 와 notify / onNotified / broadcast 검토

struct NotificationContext                       // host 에 하나. 모든 연결의 _plain.notify 를 한 mutex 가 지킨다
{
    std::mutex        mutex;
    EventListener*    listener;
    std::thread::id   io_thread;
    std::atomic<bool> queued;                    // notify 가 쌓였다. IO Thread 안에서 불린 notify 를 위해 collect 가 기다리지 않게 한다 (10.2)
    bool isIoThread() const;
};

KiottyNetCode Connection::notify(KiottyNetSpan data)                 // 아무 thread
{
    {
        std::lock_guard<std::mutex> lock(_notification.mutex);
        if (!alive())
        {
            return KIOTTY_PEER_CLOSED;
        }
        if (_plain.notify.provider().writable() < data.length)
        {
            return KIOTTY_BUFFER_FULL;
        }
        copy data into _plain.notify;                                   // 평문 그대로. 경계 헤더 없음. TLS 라도 여기서 암호화하지 않는다
    }
    _notification.queued.store(true);
    if (!_notification.isIoThread())
    {
        _notification.listener->wake();
    }
    return KIOTTY_SUCCESS;
}

IoAction Connection::onNotified()                                    // IO Thread. broadcast 와 onSent(NOTIFY) 가 부른다. 콜백 없음
{
    if (_notify_event.pending())
    {
        return IoAction::none();                                        // 걸린 notify 가 돌아오면 onSent(NOTIFY) 가 다시 부른다
    }
    if (!alive())
    {
        return IoAction::none();                                        // IDLE 과 CLOSING. broadcast 가 slot 을 전부 돌아도 여기서 끝난다
    }
    std::lock_guard<std::mutex> lock(_notification.mutex);
    size_t plain = _plain.notify.consumer().readable();
    if (plain == 0)
    {
        return IoAction::none();
    }
    if (_tls.active())
    {
        KiottyNetSpan span = { _plain.notify.consumer().peek(), plain };
        _tls.encode(span, _tls.cipher().notify);                        // SSL_write 는 IO Thread 에서, submit 순서대로
        _notify_plain_length = plain;
    }
    return IoAction::write(IoPurpose::NOTIFY, 0);
}

KiottyNetCode ConnectionHost::broadcast(KiottyNetSpan data)          // 아무 thread. 하나라도 모자라면 아무 데도 안 쓴다
{
    std::lock_guard<std::mutex> lock(_notification.mutex);
    for (size_t i = 0; i < _capacity; ++i)
    {
        Connection& c = _slots[i];
        if (c.alive() && c.notificationWritable() < data.length)
        {
            return KIOTTY_BUFFER_FULL;
        }
    }
    for (size_t i = 0; i < _capacity; ++i)
    {
        Connection& c = _slots[i];
        if (c.alive())
        {
            c.appendNotification(data);
        }
    }
    _notification.queued.store(true);
    if (!_notification.isIoThread())
    {
        _notification.listener->wake();
    }
    return KIOTTY_SUCCESS;
}
  • 암호화가 IO Thread 인 이유 둘: SSL* 은 thread-safe 가 아니다. TLS 레코드는 순서가 있어서 encode 순서와 submit 순서가 같아야 하고 그것은 한 thread 에서만 보장된다. cipher().notify 가 cipher().send 와 다른 Stage 인 이유는 둘이 동시에 걸리기 때문이다.
  • 같은 socket 에 걸린 send 둘 (USER 와 NOTIFY) 은 건 순서대로 나간다. IOCP 는 overlapped WSASend 순서, epoll 흉내는 listener 가 순서대로 send.
  • Notification Stage 의 compact 는 걸린 send 가 없을 때만 (consumeNotification 끝, lock 안).
  • instant (동기 송신) 는 넣지 않는다. 걸린 overlapped send 와 순서가 섞이고 TLS 면 레코드 순서가 깨진다. 실시간성은 10.2 의 broadcast 우선과 no_delay 로 잡는다.
  • _phase 가 atomic 인 이유는 alive() 를 notify 와 broadcast 가 다른 thread 에서 읽기 때문이다. 쓰는 쪽은 IO Thread 하나다.

10.2 한 바퀴 : collect → broadcast → step → settle

phase 는 넷이고, completion 하나는 step 안에서 dispatch → submit 을 한 줄로 지난다. 상태를 읽어 판단하는 줄은 pending() 셋이다: onTimeout (11절), settle 의 slot 반납과 Acceptor 재무장, onNotified 의 "notify 가 걸려 있나". 콜백이 나가는 자리는 step (dispatch, access → admit) 만이고, listener 를 부르는 자리는 collect (wait) 와 submit 만이다.

┌───────────┐ IoCompletion[] ┌─────────────┐ ┌──────────────────────────────┐ ┌──────────┐ │ 1 collect │───────────────▶│ 2 broadcast │─────────────▶│ 3 step (completion 마다) │─────────────▶│ 4 settle │ └───────────┘ └─────────────┘ │ dispatch ─▶ IoAction ─▶ submit │ └──────────┘ wait + TIMEOUT + WORK_DONE slot 마다 onNotified └──────────────────────────────┘ CLOSING 이고 두 event 가 비면 slot 반납 queued 면 기다리지 않는다 → submit(WRITE(NOTIFY) 또는 NONE) Acceptor 가 비어 있고 host 가 full 이 아니면 ACCEPT stop_when_empty
KiottyNetCode IoLoop::run(const Handler& handler, KiottyNetAppContext app_context)
{
    _handler = &handler;
    _app_context = app_context;
    _host.notification().io_thread = std::this_thread::get_id();
    _host.notification().listener = &_listener;
    if (_acceptor)
    {
        submit(*_acceptor, IoAction::accept());                                // 첫 accept. 그 뒤는 settle 이 다시 건다
    }
    while (!_stopped)
    {
        runOnce();
    }
    shutdown();
    return KIOTTY_SUCCESS;
}

void IoLoop::runOnce()
{
    Span<const IoCompletion> completions = collect();
    broadcast();                                                               // 깨어났으면 notify 부터. 사용자 콜백보다 먼저
    for (const IoCompletion& completion : completions)
    {
        step(completion);
    }
    settle();
}

Span<const IoCompletion> IoLoop::collect()                                    // 시계와 다른 thread 의 CAS 를 보는 유일한 자리
{
    uint32_t timeout = nearestDeadline(monotonicMs());
    if (_host.notification().queued.load())
    {
        timeout = 0;                                                           // IO Thread 안의 notify 가 있으면 기다리지 않는다
    }
    Span<const IoCompletion> waited = _listener.wait(timeout);
    size_t count = copy(waited, _completions);
    uint64_t now = monotonicMs();
    for (int32_t i = 0; i < _host.capacity(); ++i)
    {
        Connection& c = _host.at(i);
        if (c.expireDeadline(now))
        {
            _completions[count++] = IoCompletion::timeout(i);
        }
        if (c.workFinished())
        {
            _completions[count++] = IoCompletion::workDone(i);
        }
    }
    return Span<const IoCompletion>{ _completions, count };
}

void IoLoop::broadcast()                                                       // IO Thread 의 flush. 공개 broadcast(span) 과 이름은 같지만 인자가 없다
{
    _host.notification().queued.store(false);
    for (int32_t i = 0; i < _host.capacity(); ++i)
    {
        Connection& c = _host.at(i);
        IoAction action = c.onNotified();                                      // 비었거나 걸려 있거나 IDLE 이면 NONE
        submit(c, action);
    }
}

void IoLoop::step(const IoCompletion& completion)
{
    IoSource* source = nullptr;
    IoAction  action = IoAction::none();
    switch (completion.kind)
    {
    case IoKind::WAKE:
        return;                                                                // 깨우기만. broadcast 와 run 의 while 이 본다
    case IoKind::ACCEPT:
        source = _acceptor;
        action = access(completion);
        break;
    case IoKind::RECEIVE:
    case IoKind::SEND:
    case IoKind::TIMEOUT:
    case IoKind::WORK_DONE:
    {
        Connection& c = _host.at(completion.slot);
        source = &c;
        action = c.dispatch(completion, *_handler);
        break;
    }
    }
    submit(*source, action);                                                   // 한 번
}

IoAction IoLoop::access(const IoCompletion& completion)                       // ACCEPT 완료 → 연결 하나 → Acceptor 의 다음 action
{
    if (completion.code == SocketCode::CANCELLED)
    {
        return IoAction::none();                                               // shutdown 이 acceptor 를 닫았다
    }
    if (completion.code != SocketCode::SUCCESS)
    {
        _handler->onError(_app_context, 0, toNetCode(completion.code), "accept failed");
        return IoAction::accept();
    }
    Result<SocketCode, ActiveSocket> accepted = _acceptor->accept();
    if (!accepted)
    {
        _handler->onError(_app_context, 0, toNetCode(accepted.code()), "accept failed");
        return IoAction::accept();
    }
    admit(std::move(accepted.value()), nullptr);
    if (_host.full())
    {
        return IoAction::none();                                               // slot 이 없으면 걸지 않는다. backlog 가 받는다. settle 이 다시 건다
    }
    return IoAction::accept();
}

void IoLoop::admit(ActiveSocket&& socket, const char* hostname)               // 새 연결 하나. access 와 EventClient::run 이 쓴다
{
    KiottyNetConnectionDecision decision = _handler->onConnected(_app_context, socket.peer());   // handle 없이 묻는다. slot 은 아직 안 잡았다
    if (!decision.accepted)
    {
        socket.close();
        return;
    }
    Connection& c = *_host.acquire();                                          // accept 는 full 이 아닐 때만 걸었다
    c.open(std::move(socket), decision.connection_context, _app_context, _profile, hostname);
    _listener.attach(c.socket(), c.slot());                                    // 연결당 한 번
    IoAction first = c.onOpened(*_handler);                                    // 평문 : onReady 의 것. TLS : READ / WRITE (HANDSHAKE)
    submit(c, first);
}

void IoLoop::submit(IoSource& source, const IoAction& action)                 // resolve → listener. kind 별 한 줄. 콜백 없음
{
    switch (action.kind)
    {
    case IoActionKind::NONE:
    case IoActionKind::HOLD:
    case IoActionKind::START_WORK:
        return;                                                                // 걸 것이 없다. deadline 과 Work 는 dispatch 의 apply 가 끝냈다
    case IoActionKind::CLOSE:
        _listener.detach(source.socket(), source.slot());                      // 걸려 있던 요청은 CANCELLED 완료로 돌아온다
        source.close();
        return;
    case IoActionKind::READ:
    case IoActionKind::READ_UNTIL:
    case IoActionKind::WRITE:
    case IoActionKind::ACCEPT:
        _listener.submit(source.eventFor(action), source.socket(), action, source.resolve(action));
        return;
    }
}

void IoLoop::settle()
{
    for (int32_t i = 0; i < _host.capacity(); ++i)
    {
        Connection& c = _host.at(i);
        if (c.phase() != Phase::CLOSING)
        {
            continue;
        }
        if (c.streamEvent().pending() || c.notifyEvent().pending())
        {
            continue;                                                          // 늦은 완료가 아직 돌아오지 않았다
        }
        _host.release(c);
    }
    if (_acceptor && !_stopped && !_acceptor->event().pending() && !_host.full())
    {
        submit(*_acceptor, IoAction::accept());                                // 꽉 찼다가 비었다
    }
    if (_stop_when_empty && _host.empty())
    {
        _stopped = true;
    }
}

void IoLoop::shutdown()                                                        // run 의 끝. Owner 의 close
{
    if (_acceptor)
    {
        submit(*_acceptor, IoAction::close(KIOTTY_CLOSED));                    // 걸린 ACCEPT 는 CANCELLED 로 돌아오고 access 가 NONE
    }
    for (int32_t i = 0; i < _host.capacity(); ++i)
    {
        Connection& c = _host.at(i);
        if (!c.alive())
        {
            continue;
        }
        IoAction closing = c.apply(IoAction::close(KIOTTY_CLOSED), *_handler);   // onDisconnected. WORKING 도 바로
        submit(c, closing);                                                    // detach + close
    }
    while (!_host.empty())
    {
        runOnce();                                                             // CANCELLED 완료가 다 돌아올 때까지 (IOCP). epoll 은 한 바퀴
    }
}

handler 안에서 notify 를 부르면 그 바퀴의 broadcast 는 이미 지났으므로 다음 바퀴의 첫 broadcast 에서 나간다. collect 는 queued 면 기다리지 않으니 추가 지연은 "지금 바퀴의 남은 step 과 settle" 이다. 그 handler 가 길면 그만큼 늦는다. 콜백은 짧고 긴 일은 Work 라는 전제가 push 의 실시간성을 정한다. 다른 thread 의 notify 는 wake → collect 복귀 → broadcast 로, 콜백 하나를 기다리지 않는다.

11. TIMEOUT 과 CLOSE 의 흐름 이번

cancel 이 없으므로 "걸린 요청이 있는데 다른 action 이 왔다" 가 생길 수 있는 자리를 전부 세고 각각 어떻게 닫히는지 적는다. 그런 자리는 TIMEOUT 하나다. RECEIVE / SEND 완료 뒤에는 그 event 가 방금 비었고, WORK_DONE 때는 Work 중에 아무것도 걸지 않았으므로 비어 있다 (notify event 는 별개의 줄이라 겹치지 않는다).

TIMEOUT 이 생기는 자리 collect 가 now ≥ _deadline 인 연결마다 IoCompletion { TIMEOUT, slot } 을 만든다. _deadline 은 0 이 된다. _deadline 은 마지막 apply 가 action 의 timeout_ms 로 건 것이다. 그러니 "무엇을 기다리다 만료됐나" 는 _stream_event.pending() 이 말한다. (a) 걸린 요청이 없다 : HOLD 뒤, 또는 notify 만 걸려 있다 collect ─▶ TIMEOUT ─▶ onTimeout : handler.onTimeout ─▶ adopt ─▶ 어떤 action 이든 ─▶ apply ─▶ submit 평소와 같다 (b) READ / READ_UNTIL / WRITE 가 걸려 있다, handler 가 CLOSE 를 돌려줬다 collect ─▶ TIMEOUT ─▶ onTimeout ─▶ extend ─▶ CLOSE ─▶ apply : _phase = CLOSING, onDisconnected ─▶ submit : detach, socket.close │ IOCP : closesocket 이 걸린 WSARecv / WSASend 를 끊는다 ─▶ 다음 collect 에 RECEIVE { code CANCELLED } ─▶ onReceived : CLOSING 이라 NONE epoll : detach 가 걸린 event 마다 CANCELLED 완료를 자기 배열에 넣는다 ──────────────────────────▶ 같은 길 ▼ settle : 두 event 가 비었다 ─▶ slot 반납 "끊는다" 는 socket 을 닫는 것 하나다. 요청은 completion 으로만 비워진다. (c) READ / READ_UNTIL / WRITE 가 걸려 있다, handler 가 CLOSE 가 아닌 것을 돌려줬다 collect ─▶ TIMEOUT ─▶ onTimeout ─▶ extend ─▶ HOLD(ms) / READ(ms) / READ_UNTIL(ms) ─▶ 걸린 요청은 그대로. _deadline 만 다시 건다 (연장) ─▶ NONE ─▶ submit 할 것 없음 ─▶ WRITE / START_WORK ─▶ 걸린 요청 위에 겹칠 수 없다. onError(KIOTTY_BUSY, "action rejected: io outstanding. use notify") 뒤 같은 timeout 으로 연장 extend 는 adopt 를 거치지 않는다. WRITE 의 span 이 Stage 에 복사되지 않으니 거부된 데이터가 다음 WRITE 에 섞이지 않는다. "timeout 에 뭔가 보내고 싶다" 는 notify 다. notify 는 _notify_event 라 겹치지 않고, broadcast 가 다음 바퀴 첫머리에 건다. (d) HANDSHAKING 의 TIMEOUT collect ─▶ TIMEOUT ─▶ onTimeout : onError(KIOTTY_TLS_HANDSHAKE_TIMEOUT) ─▶ CLOSE ─▶ (b) (e) Work 중 START_WORK 가 _deadline 을 0 으로 했으므로 TIMEOUT 은 오지 않는다. worker 가 finishWork 로 가져오는 action 이 다음 deadline 을 건다.

11.1 CLOSE 의 공통 순서

CLOSE 가 어디서 오든 (handler 의 return, onPeerGone, handshake 실패, worker 의 outcome, Owner 의 close) 순서는 하나다.

apply(CLOSE) : _deadline = 0, _phase = CLOSING, handler.onDisconnected(app, context, handle, reason) ← 콜백은 여기. onConnected 가 accept 한 연결은 반드시 한 번 submit(CLOSE) : listener.detach(socket, slot), source.close() (shutdown + closesocket) ← listener 는 여기 그 뒤 : 걸려 있던 요청마다 CANCELLED 완료 → onReceived / onSent 가 CLOSING 을 보고 NONE settle : 두 event 가 비면 host.release → phase IDLE → slot 은 다음 accept 가 쓴다. generation 은 open 이 올린다

slot 반납을 CLOSE 자리가 아니라 settle 에서 하는 이유는 IOCP 다. 닫은 socket 에 걸려 있던 요청은 ERROR_OPERATION_ABORTED 완료로 돌아온다. slot 을 바로 재사용하면 그 늦은 완료가 새 연결의 것으로 보인다. "두 event 가 비기 전까지 CLOSING" 으로 두면 completion 에 generation 을 싣지 않아도 된다. epoll 은 detach 가 바로 CANCELLED 를 만들어 같은 바퀴의 다음 collect 에서 비고, 같은 모양으로 반납된다.

KiottyNetCode StreamClient::connect()
{
    Result<KiottyNetCode, ActiveSocket> connected = connectWithRetry(_config, _stop);
    if (!connected)
    {
        return connected.code();
    }
    _socket = std::move(connected.value());
    if (!_tls_profile.valid())
    {
        return KIOTTY_SUCCESS;
    }
    KiottyNetCode opened = _tls.open(_tls_profile, _config.endpoint.host);
    if (opened != KIOTTY_SUCCESS)
    {
        return opened;
    }
    for (;;)                                                                   // Connection 의 onHandshake 가 completion 마다 한 걸음 가는 것을 여기서는 돈다
    {
        TlsStep step = _tls.handshake();
        if (step == TlsStep::DONE)
        {
            return KIOTTY_SUCCESS;
        }
        if (step == TlsStep::FAILED)
        {
            return _tls.lastCode();
        }
        KiottyNetCode code = KIOTTY_SUCCESS;
        if (step == TlsStep::SEND)
        {
            code = sendAll(_tls.cipher().send, _config.connect_timeout_ms);
        }
        else
        {
            code = receiveSome(_tls.cipher().receive, _config.connect_timeout_ms);
        }
        if (code != KIOTTY_SUCCESS)
        {
            return code;
        }
    }
}

KiottyNetResult StreamClient::read(void* buffer, size_t length, uint32_t timeout_ms)
{
    while (_receive_stage.consumer().readable() == 0)                          // 남은 평문이 있으면 그것부터
    {
        Stage& in = _tls.active() ? _tls.cipher().receive : _receive_stage;
        KiottyNetCode code = receiveSome(in, timeout_ms);
        if (code != KIOTTY_SUCCESS)
        {
            return failure(code);
        }
        if (_tls.active())
        {
            code = _tls.decode(_receive_stage);                                // 0 바이트면 다시 돈다
        }
        if (code != KIOTTY_SUCCESS)
        {
            return failure(code);
        }
    }
    return copyOut(buffer, length);
}

KiottyNetResult StreamClient::write(KiottyNetSpan data, uint32_t timeout_ms)
{
    if (!_tls.active())
    {
        KiottyNetCode code = sendAll(data, timeout_ms);
        return result(code, data.length);
    }
    for (each chunk of data, send_capacity 씩)
    {
        _tls.encode(chunk, _tls.cipher().send);
        KiottyNetCode code = sendAll(_tls.cipher().send, timeout_ms);
        if (code != KIOTTY_SUCCESS)
        {
            return failure(code);
        }
    }
    return success(data.length);
}
