http ↔ websocket 경계 설계 v0 (초안) : R7

2026-11-17 초안. 계획 docs/plan/plan_base_261116.md 의 R7: HttpUpgradeHandler 의 answer / step / end 가 session 통째 대신 필요한 것만 받는다. 클라이언트가 HttpSessionHost 를 통째로 빌리지 않고 자기 state 를 가진다. WebSocketHandler 의 공개 필드를 정리한다. 완료 조건: websocket 이 http 의 session / host 를 include 하지 않는다, websocket 테스트 그대로. 동작과 공개 API 는 바꾸지 않는다.

1. 지금

websocket 의 서버 쪽은 http 가 넘긴 HttpSession& 위에서 돈다. 함수 스물 개 정도가 HttpSession& 를 받고, handlerOf(session) 은 session.host.upgrade 를 WebSocketHandler 로 바꾼 것이다. 실제로 꺼내 쓰는 것은 아래뿐이다.

꺼내는 것어디서무엇에
session.request.request()upgrade, message, opening, frameUpgrade 헤더 검사, connection handle, 모은 message (request.body)
session.request.appendBody / beginmessagemessage 조각을 http 요청 body 버퍼에 모은다. 다 받으면 비운다
session.response.begin / setStatus / addHeaderupgrade101 또는 거절 응답
session.state.persistence / phase / framing / sentupgrade, openingUPGRADE / CLOSE 를 적고, 101 을 websocket 이 직접 pieceAt 으로 보내며 sent 를 센다
session.idhandler, opening, upgradeindex 로 자기 칸 (SocketState, SocketLink), value() 로 앱의 socket handle
session.host.limits / receive_capacity / app_contextframe, control, timing, messagemessage 상한 (max_body_bytes), ping / pong / close 시각, 읽기 크기, 콜백의 app_context
host.sessions.find(id), session.infoaccess (다른 thread 의 send / close / info)handle 이 살아 있는지, 연결 정보

클라이언트는 더 깊다. WebSocketClient 가 HttpSessionHost 하나 (session 풀 1 칸, registry 1 칸, notices) 를 가지고, http 의 HttpState 이름, readLine, startHeaderClock / headerTimeLeft, advanceSession 을 그대로 쓴다. 101 응답의 헤더는 요청 store 의 takeHeader 로 담는다.

2. 서버: http 가 빌려주는 것을 값 하나로

// http/data/repository/upgrade/kiotty_http_upgrade_handler.h
struct UpgradeSession                        // http 가 answer / open / step / end 마다 session 에서 만들어 넘긴다
{
    const KiottyNetHttpRequest&  request;  // 요청 view: 헤더, connection
    HttpResponseStore&           response; // 101 또는 거절 응답을 쓴다 (answer 만)
    Span<char>                   message;  // 요청 body 버퍼를 빌려준다. message 조각을 모으는 곳
    const KiottyNetHttpLimits&   limits;   // max_body_bytes, ping / pong / close
    KiottyNetAppContext          app_context;
    PoolHandle                   id;       // index 로 websocket 의 칸, value() 로 앱의 handle
};

class HttpUpgradeHandler
{
public:
    virtual UpgradeAnswer       answer(const UpgradeSession& upgrade, int32_t upgrade_route) = 0;  // 응답을 쓰고 { ACCEPT | REFUSE } 를 돌려준다
    virtual KiottyNetTransition open(const UpgradeSession& upgrade) = 0;                       // 101 을 다 보낸 뒤. on_open, frame 읽기 시작
    virtual KiottyNetTransition step(const UpgradeSession& upgrade, KiottyNetConnectionEvent event) = 0;
    virtual void                end(const UpgradeSession& upgrade, KiottyNetCode reason) = 0;
};
  • http 가 자기 칸을 쓴다. answer 는 UpgradeAnswer 값만 돌려주고, persistence (UPGRADE / CLOSE), phase 는 http 가 그 값을 보고 한 번 적는다 (R4b 의 값 흐름과 같은 모양). websocket 은 HttpSessionState 를 모른다.
  • 101 은 http 가 보낸다. 다른 응답과 같은 sendStepOf 길로 보내고, 끝에서 persistence == UPGRADE 면 UPGRADED 로 가며 open(upgrade) 를 부른다. websocket 의 sendOpening 과 session.state.sent 사용이 없어진다.
  • message 버퍼는 지금처럼 빌린다. 연결마다 max_body_bytes 를 새로 잡지 않는다 (메모리 그대로). 모은 길이는 websocket 의 SocketState 가 센다 (지금은 요청 store 가 센다).
  • websocket 의 함수는 HttpSession& 대신 (WebSocketHandler&, const UpgradeSession&) 를 받는다. handlerOf(session) 은 없어진다 (handler 는 this).
  • 다른 thread 의 access 는 http 의 session 풀 대신 websocket 의 SocketLink 를 본다. open 때 링크에 handle 값과 연결 정보를 적고, send / close / info 는 그것만 확인한다.

3. 클라이언트: 자기 state

// websocket/data/state/kiotty_websocket_client_state.h
struct WebSocketClientState
{
    UpgradeText          request;     // 보낼 Upgrade 요청 (지금 _request)
    HttpReplyStore       reply;       // 101 응답의 상태줄과 헤더. HttpClient 와 같은 저장소 (R5)
    std::vector<char>    message;     // message 를 모으는 곳 (max_body_bytes)
    SocketState          socket;      // 서버와 같은 frame 단계가 쓰는 칸
    ClientEvents         events;      // on_open / on_message / on_close
    KiottyNetHttpErrorAction on_error;
    ...                                // accept, protocols, peer, opened, failure (지금 ClientUpgrade)
};
  • HttpSessionHost, session 풀, registry 1 칸, HttpState 를 쓰지 않는다. 상태 기계는 websocket 의 자기 상태 (SENDING_UPGRADE, STATUS_LINE, HEADER_LINE, OPEN, CLOSING) 로, 줄 읽기는 base 의 thenReadUntil 로 한다.
  • 101 응답은 HttpReplyStore::takeStatusLine / takeHeader 로 담는다 (요청 store 를 응답에 쓰던 어긋남이 없어진다). 응답 쪽 헤더 상한은 지금과 같은 limits.
  • frame 단계 (stepFrame, message, control) 는 서버와 같다. 클라이언트는 자기 state 로 UpgradeSession 와 같은 값을 만들어 넘긴다 (message 버퍼는 자기 vector).
  • 메모리: 지금 1 칸 풀이 잡던 응답 버퍼 (response_bytes) 가 빠지고, 헤더 버퍼는 HttpReplyStore 로. 늘지 않는다.

결정 (2026-11-17, 사용자): 1 은 (a) 로 하되 이름은 UpgradeSession (session 의 내용이고, http 의 session 과는 다른 뜻의 session). 2, 3, 4 는 (a).
