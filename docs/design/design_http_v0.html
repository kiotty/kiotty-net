설계 방침

  1. 새 개념은 없다. SSE 는 base 의 Work 모양 (worker 가 Stream 에 동기 write) 을 HTTP 의 이름으로 드러낸 것이다. 새 객체, 새 thread, 새 버퍼 클래스는 두지 않는다.
  2. HTTP 는 Session 하나와 표 하나다. design_statemachine_v0.md 11절 그대로. 라이브러리의 표가 Connection 을 밟고 사용자 콜백은 transition action 안에서 불린다. 사용자는 표를 보지 않는다.
  3. 오타가 날 자리를 이름으로 막는다. status 는 KiottyNetHttpStatus, content type 은 KiottyNetHttpContentType. 목록 밖의 content type 은 CUSTOM 과 문자열 함수 하나로만 들어온다. content type 은 body 를 정할 때만 적는다.
  4. JSON 은 라이브러리 밖이다. HTTP 층은 body 를 바이트로 다룬다. MCP 를 만드는 앱이 JSON 라이브러리를 가져다 쓴다. 라이브러리가 body 에 하는 검사는 텍스트 계열 content type 의 UTF-8 하나다.
  5. 메모리는 create 때 끝난다. 라우트 표와 Session 배열 (max_clients 개) 을 createHttpServer 가 잡는다. run 중 할당 0 (수칙 1.1, DV1).

2. base 에 먼저 필요한 것

둘 다 HTTP 와 무관하게 base 의 성질이고, WebSocket (send, pong, broadcast) 이 바로 쓴다. HTTP 의 H1 앞에 base 사이클 B1 로 한다. 공개 API 의 변경은 2.2 의 설정 필드 하나, configure 함수 둘, 코드 하나다.

  • 평문 notify 의 payload 는 지금처럼 "pick 이 본 readable 의 시작 + 그 길이" 다. pick 과 resolve 사이에 다른 thread 가 뒤에 붙인 것은 다음 WRITE 다 (compact 는 release 에서만).
  • requirement 4절의 "송신 순서" 를 이 규칙으로 고친다 (지금은 "write lane 먼저", 코드는 "notify 먼저" 로 서로 다르다). "WORKING 인 연결에서는 push lane 만 보낸다" 도 코드 (Work 중에는 아무것도 보내지 않는다) 에 맞춘다.
  • notify 에 여러 조각을 넣는 일 (WebSocket 의 frame 머리 + payload) 은 NotificationDesk 가 한 lock 안에서 이어 복사하고, 전부 들어가지 않으면 하나도 넣지 않는다 (BUFFER_FULL). 공개 API 는 그대로다.

  • 알림. 콜백 API 는 onDisconnected(..., KIOTTY_NET_CODE_PEER_NOT_READING), StateMachine 은 CLOSED 이벤트의 reason. HTTP 와 WebSocket 은 그 reason 을 그대로 쓴다 (WebSocket 은 onClose 의 code, status 1006).
  • 기본값. 30000 (1절 결정 12). 끊긴 클라이언트는 자기가 가진 session 정보 (MCP 의 Mcp-Session-Id, 게임의 session 토큰) 로 다시 연결해 이어 간다. 0 은 무한이라는 규칙 (statemachine 설계의 결정) 을 지킨다.
  • 대상 밖. Work 중 worker 의 동기 write (writeConnectionStream, writeHttpWorkChunk) 는 호출마다 자기 timeout 이 있고 TIMEOUT 을 돌려준다. worker 가 thread 를 오래 붙잡는 것은 사용자의 handler 과실로 보고 라이브러리가 재지 않는다.
  • push Stage 가 차서 notify 가 BUFFER_FULL 을 돌려주는 동안에도 그 연결의 WRITE 는 걸려 있으므로, 읽지 않는 상대는 결국 이 timeout 으로 끊긴다.

3.2 Work 스트림 추가

IO thread : READ(요청 끝) → onRequest { 검사, startHttpWork } → return → [Working] thenWork → WORK_STARTED → onWorkStarted(request, response, work) → worker 에 넘김 worker : setHttpStatus(response, KIOTTY_NET_HTTP_STATUS_OK), setHttpHeader(response, "Cache-Control", "no-cache") setHttpBodyStream(response, KIOTTY_NET_HTTP_CONTENT_TYPE_EVENT_STREAM) writeHttpWorkChunk(work, "event: message\ndata: {...}\n\n", 5000) ← 첫 write 가 상태줄 + 헤더 + chunk writeHttpWorkChunk(work, ...) ← chunk 하나씩. 보내는 즉시 나간다 ... (PEER_CLOSED / TIMEOUT / CLOSED 면 finishHttpWorkWithClose 하고 끝) finishHttpWorkWithResponse(work) ← 끝 chunk "0\r\n\r\n" IO thread : WRITTEN → keep-alive 면 [ReadingRequestLine], 아니면 close
  • writeHttpWorkChunk 는 KiottyNet_writeConnectionStream 위에 있다. 동기이고, 전부 보내거나 실패하고, timeout 0 은 무한이고, 돌아오면 data 는 버려도 된다.
  • 라이브러리가 data 에 chunk 머리 (길이 hex CRLF) 와 꼬리 (CRLF) 를 씌운다. 사용자가 0\r\n\r\n 을 직접 쓰지 않는다 (data 로 쓰면 그것도 chunk 하나로 감싸진다). 빈 data 는 INVALID_ARGUMENT (길이 0 chunk 는 끝이다).
  • body 종류가 텍스트 계열 (EVENT_STREAM 포함) 이면 chunk 마다 UTF-8 을 본다. 그래서 문자 하나를 두 chunk 에 나눠 쓰면 안 된다. SSE 이벤트는 줄 단위라 그럴 일이 없다.
  • 첫 write 뒤의 setter (setHttpStatus, setHttpHeader, body setter) 는 BUSY 다. 헤더가 이미 나갔다.
  • 스트림 body 는 Work 안에서만 된다. onRequest 안에서 setHttpBodyStream 을 불렀는데 startHttpWork 없이 return 하면 라이브러리가 500 을 보내고 닫는다 (보낼 사람이 없다).
  • 끝을 따로 알릴 콜백은 없다. 상대가 끊으면 다음 write 가 PEER_CLOSED, 서버가 close 하면 CLOSED 를 돌려준다. 이벤트가 없는 동안 끊김을 빨리 알려면 worker 가 기다리다가 주기적으로 : ping\n\n 을 쓰거나 isHttpWorkConnected 를 본다.
  • GET 스트림처럼 오래 가는 스트림은 그동안 worker 하나를 쓴다. 동시 스트림 수만큼 worker 가 필요하다. 장비 하나에 MCP 클라이언트 몇 개라는 전제다.

    • onDisconnected 는 연결마다 한 번, 끝나는 이유와 함께 온다: SUCCESS (keep-alive 아님, 다 보냄), TIMEOUT (header / keep-alive timeout), PEER_CLOSED, PEER_NOT_READING (send timeout), PROTOCOL_ERROR (400 / 413 / 414 / 431 / 501 뒤), CLOSED (서버 close). connection 은 request->connection 과 같은 값이라 앱이 요청과 이을 수 있다. 이 콜백 안에서 그 handle 은 이미 무효이므로 주소는 info 로 본다.
    • onError 는 연결이 생기기 전이나 연결과 따로 생기는 문제다: TABLE_FULL (연결 수 초과), TLS_* (handshake 실패), accept 실패. base 의 onError 가 받는 것을 그대로 넘긴다. 잘못된 요청은 onDisconnected 의 reason 으로 오고 onError 로 두 번 오지 않는다.
    • 요청 단위의 성공은 알리지 않는다 (라우트가 안다). onConnected (받을지 거절할지) 는 두지 않았다. IP 허용 목록이 필요해지면 그때 더한다.
  • HEAD. 라이브러리가 GET 라우트 (와 정적 경로) 로 처리하고 body 바이트만 보내지 않는다. onRequest 는 request->method 로 HEAD 인 것을 알 수 있지만 따로 처리하지 않아도 된다.
    • 완성 응답: Content-Length 는 GET 일 때의 길이를 적고 body 를 떼고 보낸다.
    • onRequest 에서 setHttpBodyStream 을 하고 startHttpWork 를 부른 스트림 라우트: HEAD 면 Work 를 열지 않는다. startHttpWork 는 SUCCESS 이고 onWorkStarted 는 불리지 않으며, 그때까지 놓인 status, 헤더, Content-Type, Transfer-Encoding: chunked 만 보내고 keep-alive 로 다음 요청을 읽는다. 그래서 스트림 라우트는 status 와 body 종류를 onRequest 에서 정하는 것을 권한다 (6절 예제).
    • 그 밖의 Work (body 종류를 worker 가 정하는 것): Work 를 그대로 연다. worker 가 완성 응답으로 끝내면 body 를 떼고 보낸다. worker 가 스트림을 열면 첫 writeHttpWorkChunk 가 헤더만 보내고 CLOSED 를 돌려준다 (응답이 끝났다). worker 의 루프는 실패한 write 에서 이미 빠져나오므로 따로 처리할 것이 없다.
  • 정적 서빙은 GET / HEAD 만 받는다. 다른 메서드는 405 + Allow: GET, HEAD, OPTIONS. 디렉토리 밑의 .. 는 403, 없는 파일은 404 (user_guide 1.6 그대로).

6. 예제 : MCP 서버

엔드포인트 /mcp 하나에 POST (JSON-RPC. 응답은 JSON 하나이거나 SSE), GET (서버 → 클라이언트 스트림), DELETE (세션 종료). JSON 과 세션 표는 앱의 것이고 여기서는 라이브러리 호출만 보인다.

#include "kiotty_net_http.h"

struct McpApp
{
    WorkerPool   pool;
    SessionTable sessions;                    // Mcp-Session-Id → 상태와 이벤트 큐 (서버가 먼저 보낼 메시지). 앱이 잠근다
};

static void onPost(KiottyNetAppContext app_context, const KiottyNetHttpRequest* request, KiottyNetHttpResponseHandle r)
{
    McpApp*                app = static_cast<McpApp*>(app_context);
    KiottyNet_HttpResponse response(r);
    KiottyNetSpan          accept  = KiottyNet_findHttpHeader(request, "Accept");
    KiottyNetSpan          session = KiottyNet_findHttpHeader(request, "Mcp-Session-Id");
    if (!acceptsJsonAndEventStream(accept))
    {
        response.status(KIOTTY_NET_HTTP_STATUS_NOT_ACCEPTABLE);
        return;
    }
    if (!isInitialize(request->body) && !app->sessions.has(session))
    {
        response.status(KIOTTY_NET_HTTP_STATUS_NOT_FOUND);
        return;
    }
    if (isNotificationOrResponseOnly(request->body))
    {
        response.status(KIOTTY_NET_HTTP_STATUS_ACCEPTED);
        return;
    }
    response.startWork();
}

static void onPostWork(KiottyNetAppContext app_context, const KiottyNetHttpRequest* request, KiottyNetHttpResponseHandle r, KiottyNetHttpWorkHandle w)
{
    McpApp*            app = static_cast<McpApp*>(app_context);
    std::string        body(request->body.data, request->body.length);
    KiottyNet_HttpWork work(w);
    app->pool.post([app, body, r, work = std::move(work)]() mutable
    {
        KiottyNet_HttpResponse response(r);
        JsonRpcRequest         rpc = parse(body);
        if (rpc.isInitialize())
        {
            std::string id = app->sessions.create();
            response.header("Mcp-Session-Id", id.c_str());
            response.body(KIOTTY_NET_HTTP_CONTENT_TYPE_JSON, span(initializeResult(rpc)));
            work.finishWithResponse();
            return;
        }
        if (!rpc.isLong())
        {
            response.body(KIOTTY_NET_HTTP_CONTENT_TYPE_JSON, span(handle(rpc)));
            work.finishWithResponse();
            return;
        }
        response.bodyStream(KIOTTY_NET_HTTP_CONTENT_TYPE_EVENT_STREAM);
        for (Progress p : run(rpc))
        {
            std::string event = "event: message\ndata: " + progressNotification(p) + "\n\n";
            KiottyNetResult sent = work.write(span(event), 5000);
            if (sent.code != KIOTTY_NET_CODE_SUCCESS)
            {
                work.finishWithClose();
                return;
            }
        }
        std::string last = "event: message\ndata: " + finalResponse(rpc) + "\n\n";
        work.write(span(last), 5000);
        work.finishWithResponse();
    });
}

static void onGet(KiottyNetAppContext app_context, const KiottyNetHttpRequest* request, KiottyNetHttpResponseHandle r)
{
    McpApp*                app = static_cast<McpApp*>(app_context);
    KiottyNet_HttpResponse response(r);
    if (!acceptsEventStream(KiottyNet_findHttpHeader(request, "Accept")))
    {
        response.status(KIOTTY_NET_HTTP_STATUS_METHOD_NOT_ALLOWED);
        return;
    }
    if (!app->sessions.has(KiottyNet_findHttpHeader(request, "Mcp-Session-Id")))
    {
        response.status(KIOTTY_NET_HTTP_STATUS_NOT_FOUND);
        return;
    }
    response.header("Cache-Control", "no-cache");
    response.bodyStream(KIOTTY_NET_HTTP_CONTENT_TYPE_EVENT_STREAM);                // 스트림의 헤더는 여기서 정한다. HEAD 면 이것만 나가고 Work 는 열리지 않는다
    response.startWork();
}

static void onGetWork(KiottyNetAppContext app_context, const KiottyNetHttpRequest* request, KiottyNetHttpResponseHandle, KiottyNetHttpWorkHandle w)
{
    McpApp*            app = static_cast<McpApp*>(app_context);
    std::string        session = textOf(KiottyNet_findHttpHeader(request, "Mcp-Session-Id"));
    std::string        last_event_id = textOf(KiottyNet_findHttpHeader(request, "Last-Event-ID"));
    KiottyNet_HttpWork work(w);
    app->pool.post([app, session, last_event_id, work = std::move(work)]() mutable
    {
        EventQueue* queue = app->sessions.attachStream(session);                // 세션당 스트림 하나. 이미 있으면 nullptr
        if (queue == nullptr)
        {
            work.finishWithClose();                                             // 헤더를 아직 안 보냈지만 status 는 이미 200 이라 닫는다
            return;
        }
        queue->replayAfter(last_event_id);                                    // 재개는 앱
        while (true)
        {
            std::string event;
            bool        has_event = queue->waitFor(event, 15000);             // 15 초마다 ping
            if (!has_event)
            {
                event = ": ping\n\n";
            }
            KiottyNetResult sent = work.write(span(event), 5000);
            if (sent.code != KIOTTY_NET_CODE_SUCCESS)
            {
                break;                                                         // 상대가 끊음, 서버 close, timeout
            }
            if (queue->closed())
            {
                work.finishWithResponse();                                     // DELETE 로 세션이 끝남. 끝 chunk
                app->sessions.detachStream(session);
                return;
            }
        }
        app->sessions.detachStream(session);
        work.finishWithClose();
    });
}

static void onDelete(KiottyNetAppContext app_context, const KiottyNetHttpRequest* request, KiottyNetHttpResponseHandle r)
{
    McpApp* app = static_cast<McpApp*>(app_context);
    app->sessions.remove(KiottyNet_findHttpHeader(request, "Mcp-Session-Id"));    // GET 스트림의 큐를 closed 로. 그 worker 가 끝 chunk 를 보낸다
    KiottyNet_HttpResponse(r).status(KIOTTY_NET_HTTP_STATUS_NO_CONTENT);
}

int main()
{
    KiottyNet_Context            context;
    KiottyNetServerConfiguration configuration;
    KiottyNet_ServerConfigurationBuilder::tcp(configuration, "127.0.0.1", 8080).maxClients(16).sendTimeout(30000).build();

7. 규칙 : thread, 수명, 코드
