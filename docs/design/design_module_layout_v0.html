모듈 정리 설계 v0 (초안) : 의존 방향, 층의 역할, 값으로 잇는 흐름

2026-11-16 초안. 파일을 base / statemachine / http / websocket 로 옮긴 뒤 (사용자 결정 2026-11-16) 드러난 것을 정리한다. 사용자 요구: 의존 방향 core ← base ← statemachine ← http ← websocket, entity 는 값만, 로직은 repository 에 관심사별로, usecases 는 C ABI 인자로 repository 를 조합, 상태는 data/state, 처리 순서는 B b = f(const A& a) 처럼 타입만으로 읽힌다. 동작은 바꾸지 않는다 (공개 API 그대로, 테스트 수 그대로).

순서가 안 보이는 까닭

서버의 한 단계는 모두 HttpSession& → KiottyNetTransition 이고 값은 session 을 거쳐 다음 단계로 간다. 넘김 조사에서 숨은 쓰기를 19 곳 찾았다. 대표:

  • takeRequestLine / takeHeader 는 code 만 돌려주고 파싱한 값은 store 에 남긴다.
  • finishHeaders 는 framing 을 돌려주면서 keep_alive 도 몰래 쓴다. afterHeaders 가 persistence, has_body 를 쓰고 한참 뒤 sendPiece 가 읽는다.
  • body_remaining 을 세 곳이 쓰고 두 곳이 읽는다.
  • 사용자 콜백 → C ABI → HttpWork::fill 이 응답과 is_work_requested 를 쓰고 afterRoute 가 그 flag 를 본다.
  • client: transmit 가 몰래 다시 연결하고 머리 영역을 지운다. nextLine 이 _has_reply_bytes 를 세우고 attempt 가 읽는다.

이미 원하는 모양인 것: upload (HttpUpload u = takeUploadPiece(u, n)), selectReplyFraming. 이것을 본으로 삼는다.

3. statemachine

지금

  • 공개 구조체 KiottyNetRule, KiottyNetStateMachine 을 구현이 그대로 쓴다 (복사도 감싸기도 없음). handle 은 없다.
  • kiotty_rule_table: 자유 함수 findRule, isAllowed, checkRules.
  • kiotty_stateful_handler: class StatefulHandler : public Handler. base 의 연결이 dispatch(caller, event) 를 부르고, 규칙을 찾아 transition action 을 부르고, 다음 상태를 검사해 쓴다.
  • 쓰는 곳: http 서버 (HTTP_MACHINE), websocket 클라이언트 (CLIENT_MACHINE), C ABI runStatefulServer / runStatefulEventClient, 테스트 (kiotty_test_rule_table.cpp 가 세 함수를 직접 부름).

바꿈

층무엇

바꿈: http 가 정의하고 websocket 이 채우는 HttpUpgradeHandler

// http/data/repository/upgrade/kiotty_http_upgrade_handler.h   (http 는 이것만 안다)
class HttpUpgradeHandler
{
public:
    virtual KiottyNetCode       reserve(size_t session_count) = 0;                    // create 때 연결별 메모리
    virtual KiottyNetTransition answer(UpgradeRequest request, HttpSession& session) = 0;   // 101 을 줄지
    virtual KiottyNetTransition step(HttpSession& session, KiottyNetConnectionEvent event) = 0;  // UPGRADED 동안
    virtual void                end(HttpSession& session, KiottyNetCode reason) = 0;           // 닫힘
};
  • 라우트: http 의 라우트 항목은 UPGRADE 종류와 정수 upgrade_index 만 갖는다. 대상 표 (WebSocketTarget) 와 콜백은 websocket 이 가진다.
  • 상태 기계: HttpState 에서 SOCKET_OPENING, FRAME_* 를 빼고 UPGRADED 하나를 둔다. UPGRADED 의 READ / WRITTEN / TIMEOUT 은 모두 handler.step 으로. frame 의 세부 상태 (머리 / 길이 / mask / payload) 는 websocket 이 자기 상태에 들고 자기 enum 으로 간다 (지금도 socket.read.state 를 따로 든다). 서버 run 은 기계 하나 (HTTP_MACHINE) 그대로.
  • 연결별 메모리: SocketState 와 SocketLink 를 http session 에서 빼서 websocket 이 create 때 reserve(count) 로 받은 배열에 둔다. session 의 index 로 찾는다. message payload 는 지금처럼 http 의 body 버퍼를 빌린다 (request.body() 를 raw span 으로 내주고 mask 풀기는 websocket 이 한다). 정할 것 4.
  • 공개 handle: KiottyNetWebSocketEndpoint 는 websocket 의 WebSocketServerEndpoint (HttpServer 와 handler 를 reference 로 듦) 가 구현한다. C ABI 는 그대로.
  • HttpServer 와의 연결: KiottyNet_addWebSocket (websocket C ABI) 이 처음 불릴 때 그 서버에 websocket 의 handler 를 붙인다. 붙지 않은 서버는 upgrade 라우트가 없으니 http 혼자 돈다.
  • websocket 클라이언트: http 의 조각 (Session, store, 파서, 상태 기계 도우미) 을 쓴다. 허용 방향이라 둔다. HttpSite 의 client 전용 필드 (upgrade, mask_state, role) 는 websocket 의 감싸개로 옮긴다.

R4w 구현 (2026-11-17): R4w-1 자리 옮기기 (b1bb486), R4w-2 frame 읽기를 값으로 (ad3e91b, UPGRADED 한 상태와 stepFrame). HttpSite 는 HttpSessionHost 로 (R4w-3, base 의 Connection / ConnectionHost 와 같은 짝). "websocket 이 http 의 session / site 를 include 하지 않음" 과 클라이언트가 host 를 통째로 빌리지 않는 것은 R7 (http ↔ websocket 경계, R6 뒤) 로 미룬다. 경계 인터페이스가 바뀌는 일이라 R5 / R6 과 함께 보아야 한다.

R6 구현 (2026-11-17): usecases 여섯 파일 (base server / client, http server / client, websocket server / client). adapter 는 null 검사, 인자 변환 (parseText, CallbackHandler, ClientRequest, ClientRun), 결과를 C 구조체로, 그리고 handle 메서드나 usecase 하나만 부른다. 오류 code 의 순서는 그대로 두려고 순서가 걸린 문자열 (응답 헤더, 파일 경로, close reason, protocol 목록) 은 usecase 가 C 문자열로 받는다. handle 크기는 base 타입과 같다는 static_assert 를 두고 메모리 크기 계산은 base 타입으로 한다.

R5 구현 (2026-11-17): HttpClientState (state/, 7절의 칸에 max_headers 를 더함), HttpClientExchange(HttpClientState&, StreamClient&) (이름은 HttpClientStream 대신 지금 것을 두었다. StreamClient::stream() 과 헷갈린다), StreamClient 공개 7 (stream() 이 StreamResult 로 연결 여부를 알린다. reconnect(address, deadline) 는 주소를 받는다. 주소는 HttpClientTarget 에만 둔다), ConnectionStream::peek(wanted, t) / consume 과 자유 함수 readLine. 6절의 값 Connected, ReplyHead (entity kiotty_http_client_step.h). friend 0.

R3 구현 (2026-11-16): 서버는 WebSocketServer : HttpServer (websocket) 가 WebSocketHandler 를 겸하고 공개 handle KiottyNetHttpServer 가 그것을 상속한다. 그래서 reserve 대신 WebSocketServer::initialize 가 배열을 만든다. UPGRADED 한 상태로 줄이는 일은 R4w 로 미뤘다 (상태 이름은 그대로, row 만 step 으로). 자세한 것은 docs/progress/261116_progress_module_layout_r3.md.

6. 값으로 잇는 흐름

규칙: 한 단계는 앞 단계의 값을 받아 새 값을 돌려준다. 다음 단계가 읽을 것은 돌려준 값에 있다. state 에 쓰는 것은 단계의 끝에서 한 번 (돌려받은 값을 저장), 이름이 store* / commit* 로 드러난다. I/O 가 사건 단위로 쪼개지므로 사건 사이의 값은 state 의 "단계 칸" 하나에 둔다.

서버: 요청 머리까지

RequestLineResult  line    = parseRequestLine(bytes);                          // REQUEST_LINE 사건
HeaderResult       header  = parseHeaderLine(bytes, limits);                   // HEADER_LINE 사건마다
RequestHeadState   head    = appendHeader(head, header.value);                 //   값 → 새 값
RequestFraming     framing = frameRequest(line.value, head);                   // 빈 줄: { body, keep_alive, expects_continue }
BodyPlan           plan    = planBody(framing);                                 // { NONE | LENGTH n | CHUNKED }
RouteMatch         match   = findRoute(registry, line.value);                  // body 끝
Answer             answer  = answer(match, request);                            // 라우트 / 정적 / upgrade / 거절
ResponseFrame      frame   = sealResponse(response, SealOf(framing, answer));  // 머리 조립
Piece              piece   = pieceAt(frame, sent);                              // WRITTEN 사건마다
AfterResponse      after   = afterResponse(framing.keep_alive, answer);        // { KEEP | CLOSE reason }
  • finishHeaders 가 몰래 쓰던 keep_alive, afterHeaders 가 쓰던 persistence / has_body 는 RequestFraming 값 안에 있다.
  • body_remaining 은 BodyPlan 값의 필드다. takeBody(plan, piece) → BodyPlan 이 줄인 새 값을 돌려준다 (upload 와 같은 모양).
  • 사용자 콜백이 쓰는 응답과 Work 요청은 콜백이 끝난 뒤 Answer collectAnswer(const ResponseDraft&) 로 값이 된다. flag 를 나중에 읽지 않는다.
  • row 함수 (상태 기계) 는 이 값들을 state 에서 꺼내 위 함수를 부르고 결과를 저장하고 Transition 을 돌려준다. row 하나 = 위 줄 하나 둘.

클라이언트: 요청 하나

ClientRequest      request = clientRequestOf(c_request, headers, count);      // usecase (C ABI 인자)
RequestHead        head    = requestHeadOf(state.target, state.shared, request, body_length);
HeadBytes          bytes   = writeRequestHead(state.head_area, head);         // 길이 있는 span
Connected          link    = ensureConnected(line, state.target, deadline);   // 다시 연결은 여기서만, 값으로 알림 { code, is_reused }
SendResult         sent    = sendBytes(line, bytes, deadline);
ReplyHead          reply   = receiveReplyHead(line, state.reply, request.method, deadline);   // { status, headers, framing, saw_bytes }
RetryPlan          retry   = planRetry(link, sent, reply, request.method);    // 지금 attempt 안의 판단
KiottyNetHttpReply answer  = replyOf(reply);

_has_reply_bytes 는 ReplyHead::saw_bytes, 몰래 하던 다시 연결은 Connected 값이 된다.

websocket 서버: upgrade 에서 message 까지

UpgradeCheck       check    = checkUpgrade(request);                          // http 가 handler.answer 를 부를 때: GET, body 없음, Upgrade / Connection / Version / Key
UpgradeChoice      choice   = callUpgrade(target, check.value, app_context);  // 앱의 on_upgrade: protocol 고르기
HandshakeReply     reply    = handshakeReplyOf(check.value.key, choice);     // 101 과 Sec-WebSocket-Accept, Sec-WebSocket-Protocol
SocketState        opened   = openSocket(target_index, choice);               // 101 을 다 보낸 뒤, on_open

FrameStartResult   start    = parseFrameStart(bytes);                         // FRAME_START 사건
FrameLengthResult  length   = parseExtendedLength(bytes);                     // FRAME_LENGTH 사건 (필요할 때)
MaskKey            key      = parseMaskKey(bytes);                            // FRAME_MASK 사건
FramePlan          plan     = planFrame(start.value, length.value, key, socket.message);  // { DATA | CONTROL, 남은 길이, 순서 맞음 }
MessageProgress    progress = appendPiece(socket.message, unmask(piece, plan));          // FRAME_PAYLOAD 사건마다, 값 → 새 값
MessageResult      message  = finishMessage(progress, plan.opcode);           // 끝 frame: UTF-8 검사 → KiottyNetWebSocketMessage
ControlAnswer      answer   = answerControl(plan, control_payload);           // PING → PONG, CLOSE → close 답과 닫기, PONG → 없음
FrameHead          head     = buildFrameHead(opcode, payload.length);         // 보내기 (다른 thread): head 와 payload 를 lane 에

지금 SocketState 를 바로 고치던 storePiece, storeControl, isInOrder 는 MessageProgress / FramePlan 값이 된다. 사건 사이에는 그 값만 state 에 저장한다.

7. HttpClient 의 State

// http/data/state/kiotty_http_client_state.h
struct HttpClientState
{
    BusyFlag           busy;
    HttpClientTarget   target;       // address, host, has_target
    HttpSharedHeaders  shared;
    HttpReplyStore     reply;
    HttpBodyReader     body;
    HttpUpload         upload;
    Persistence        persistence;
    Span<char>         head_area;
};
  • HttpClient 는 StreamClient 를 private 상속하고 State 를 멤버로 가진다. 공개 메서드: initialize, reset, connect, stream, headers, link.
  • HttpClientStream(HttpClientState&, StreamClient&) 이 send, readBody, begin, write, finish. StreamClient 의 공개 메서드만 쓴다. friend 도 새 세부 객체도 없다.
  • 바이트 일은 이미 있는 ConnectionStream (서버 Work 와 StreamClient 가 함께 씀) 이 한다. peek / consume 을 더한다 (지금 StreamClient 의 protected peekReceived, consumeReceived, stagedBytes).
  • StreamClient 공개 메서드: initialize, reset, connect, reconnect(deadline), disconnect, stream() (6). 지금 공개인 read / write 는 stream().read / stream().write 로 (StreamClient C ABI 의 번역에서). 연결 여부는 stream() 이 알려 준다.
  • HttpClientHeaders, HttpClientLink 도 State 를 받는다.
